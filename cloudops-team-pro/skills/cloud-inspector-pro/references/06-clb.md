# 06 CLB 负载均衡安全巡检

> SOP: TC-SEC-SOP-001 | 章节 06  
> 操作路径：CLB 控制台 → https://console.cloud.tencent.com/clb

## 6.1 HTTPS 与证书

| 检查项 | 操作方法 | 判定标准 | 风险等级 | 处置 |
|--------|---------|---------|---------|------|
| HTTPS 监听器 | CLB > 监听器 | 对外 HTTP(S) 必须配 HTTPS | 🟠 高 | 添加 HTTPS 监听器 |
| HTTP 跳转 | 监听器 > 重定向 | HTTP 应 301 跳转 HTTPS | 🟠 高 | 配置跳转 |
| SSL 有效期 | 证书列表 | 到期前 **30 天** 预警 | 🟠 高 | 续期/更换 |
| TLS 版本 | HTTPS > 高级 | 最低 TLS **1.2** | 🟡 中 | 升级最低版本 |

### 巡检步骤

1. 登录 https://console.cloud.tencent.com/clb
2. 进入每个 CLB 实例 > 监听器管理
3. 检查是否存在 HTTP 80 监听器但无对应 HTTPS 443 监听器
4. 检查 HTTP 80 是否配置了 301 重定向至 HTTPS
5. 前往 SSL 证书管理，检查到期时间，提前 30 天通知续期
6. 检查 HTTPS 监听器的 TLS 策略，确认最低版本 ≥ TLS 1.2

## 6.2 WAF 防护

**风险等级：🔴 严重**  
操作路径：WAF → https://console.cloud.tencent.com/guanjia

| 检查项 | 操作方法 | 判定标准 | 处置 |
|--------|---------|---------|------|
| WAF 部署 | WAF > 防护域名 | 对外 HTTP(S) 必须部署 | 接入 WAF |
| 防护模式 | WAF > 设置 | 应为**拦截模式**（非观察模式） | 切为拦截 |
| 规则更新 | WAF > 规则 | 自动更新开启 | 开启自动更新 |
| CC 防护 | WAF > CC | 应开启 CC 策略 | 配置 CC 规则 |
| IP 黑白名单 | WAF > 访问控制 | 按需配置 | 按需配置 |
| 日志记录 | WAF > 日志 | 攻击日志投递 CLS | 配置日志投递 |

### 巡检步骤

1. 登录 https://console.cloud.tencent.com/guanjia
2. 导出所有防护域名列表，与 CLB 对外域名列表做对比
3. 对未接入 WAF 的对外域名，评估优先级，推动接入
4. 检查所有已接入域名的防护模式：
   - 观察模式 → 分析近期攻击日志确认误报率 → 切换拦截模式
5. 确认 CC 防护规则已配置，规则自动更新已开启
6. 检查日志是否已投递至 CLS，方便日后审计

## 6.3 日志与健康检查

| 检查项 | 操作方法 | 判定标准 | 风险等级 |
|--------|---------|---------|---------|
| 访问日志 | CLB > 日志 | 敏感站点配 CLS 日志 | 🟡 中 |
| 健康检查 | CLB > 后端 | 所有 RS 健康检查正常 | 🟡 中 |
| CLB 安全组 | CLB > 安全组 | CLB 应绑定安全组 | 🟠 高 |
| 监听端口 | CLB > 监听器 | 检查不必要的监听端口 | 🟡 中 |

### 巡检步骤

1. 检查每个 CLB 是否绑定了安全组
2. 核查后端 RS 健康检查状态，对异常 RS 排查原因
3. 对核心业务 CLB 开启访问日志并投递至 CLS
4. 清理无业务使用的监听端口

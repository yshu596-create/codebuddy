# 12 漏洞处置与应急响应

> SOP: TC-SEC-SOP-001 | 章节 12

## 12.1 漏洞分级处置时限

| 严重程度 | 响应时限 | 修复（生产） | 修复（测试） | 处置要求 |
|---------|---------|------------|------------|---------|
| 🔴 严重 | ≤ 1 小时 | ≤ 2 小时 | ≤ 24 小时 | 立即响应，启动应急 |
| 🟠 高风险 | ≤ 1 小时 | ≤ 24 小时 | ≤ 72 小时 | 优先修复，升级通知 |
| 🟡 中风险 | ≤ 24 小时 | ≤ 72 小时 | ≤ 7 天 | 排期修复 |
| 🟢 低风险 | ≤ 48 小时 | ≤ 15 天 | ≤ 30 天 | 计划修复或接受 |

---

## 12.2 处置流程

```
发现风险（巡检工具/安全扫描）
    ↓
风险确认（安全团队分级确认，排除误报）
    ↓
通知责任人（工单/企微/邮件通知安全接口人）
    ↓
制定方案（业务侧制定修复方案）
    ↓
执行修复（业务侧执行）
    ↓
复验确认（安全团队复验闭环）
    ↓
记录归档（更新报告，记录过程）
```

---

## 12.3 安全事件应急流程

```
事件发现（巡检/告警/外部报告）
    ↓
事件评估（评估影响范围和严重程度）
    ↓
紧急止损（隔离资源：改安全组/禁账号/切网络）
    ↓
根因分析（云审计/主机安全/网络日志定位）
    ↓
修复加固（修漏洞、加固配置、清后门）
    ↓
恢复业务（确认安全后恢复）
    ↓
复盘总结（输出报告，更新策略）
```

## 12.4 密钥泄露应急处置

1. **定位泄露源**：GitHub / 内网 Git 搜索泄露密钥
2. **立即禁用**：CAM > API 密钥管理 > 禁用泄露密钥
3. **申请新密钥**：并通知所有使用方更换
4. **审计调用**：云审计查近 30 天调用记录，排查异常操作
5. **删除/转私有**：泄露代码仓库转私有或删除相关提交，通知相关方

> ⚡ **关键：发现泄露后第一步必须立即禁用密钥，速度优先于其他一切操作**

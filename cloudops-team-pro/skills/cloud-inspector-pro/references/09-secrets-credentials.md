# 09 密钥与凭据管理巡检

> SOP: TC-SEC-SOP-001 | 章节 09

## 9.1 API 密钥泄露排查

**风险等级：🔴 严重**

### 排查步骤

1. **GitHub 搜索**：前往 github.com/search，使用以下关键词搜索：
   - `AKID` + 公司相关关键词
   - `SecretId` + 公司域名
   - `cloud.tencent.com` + `SecretKey`
2. **定位子账号**：CAM 用户列表搜索对应 SecretId
3. **审计调用**：云审计查近 30 天调用记录，识别异常操作
4. **密钥安全性判定**：
   - [ ] 是否硬编码在代码中？
   - [ ] 是否明文传输？
   - [ ] 是否已过期？
   - [ ] 是否在公开环境（日志/截图/文档）中暴露？

### 发现泄露后立即执行

参见 [12-incident-response.md - 密钥泄露应急处置](12-incident-response.md#124-密钥泄露应急处置)

## 9.2 SSL 证书管理

| 检查项 | 操作方法 | 判定标准 | 风险等级 |
|--------|---------|---------|---------|
| 有效期 | SSL > 证书管理 | 到期前 **30 天** 续期 | 🟠 高 |
| 算法 | 证书详情 | RSA 2048+ 或 ECC P-256+ | 🟡 中 |
| 闲置证书 | 证书列表 | 过期/未用证书清理 | 🟡 中 |
| 私钥保护 | 存储方式 | 不得硬编码/明文存储 | 🟠 高 |
| 证书链完整 | 证书详情 | 包含完整中间证书 | 🟡 中 |

### 巡检步骤

1. 前往 SSL 证书控制台，导出所有证书列表
2. 筛选 30 天内到期的证书，通知对应业务负责人续期
3. 清理过期和闲置（未绑定任何资源）的证书
4. 核查私钥存储位置，确保没有硬编码在代码库中

## 9.3 密钥使用场景合规

| 使用场景 | 合规要求 | 参考方案 |
|---------|---------|---------|
| 后台内网使用 | 可用明文但须开启公网封禁策略 | SKAP 平台托管 |
| 公网客户端（COS 直传/STS） | 必须安全托管模式，**严禁明文** | STS + 临时密钥 |
| 代码中使用密钥 | **严禁硬编码** | KMS 白盒 / 环境变量注入 |
| CI/CD 流水线 | 使用密钥管理服务注入 | 流水线密钥变量 |
| 容器环境 | K8s Secret + 加密 | Sealed Secrets / External Secrets |

### 巡检步骤

1. 检查代码仓库是否有历史泄露记录（git log 搜索）
2. 确认 CI/CD 流水线中的密钥均通过变量注入，不写入代码
3. 核查 K8s Secret 是否开启了 etcd 加密存储
4. 对容器中使用敏感凭据的业务，评估是否迁移至 External Secrets / KMS

### 关键安全原则

> ⚠️ **任何情况下严禁将 AK/SK 硬编码在代码、配置文件或日志中**

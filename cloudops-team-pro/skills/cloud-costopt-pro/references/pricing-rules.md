# 预计月省计算口径（F6）

> 本文件是闲置巡检 Skill 的**节省金额计算权威源**。
> 所有「预计月省」建议必须**可追溯**到本文件定义的公式和系数，不允许凭感觉估算。

---

## 一、核心原则

- ❌ [HARD] **禁止编造节省金额**：每条「预计月省」必须由「基线月费 × 预估比例系数」计算得出
- ❌ [HARD] **无账单基线时禁止凭空估算**：若无法从账单获取基线月费，建议必须标注 `[基于行业经验，非实际测算]` 并**不计入总节省合计**
- ⚠️ [MUST] **金额展示整数**（F20 通用规则）：`¥680` 而非 `¥680.00`
- ⚠️ [MUST] **每条建议附计算说明**：在表格 footnote 或建议的最后一列简注 `¥X = ¥Y × Z%`
- ✅ 预估比例取行业保守值（宁可低估不可高估），给用户留余量

---

## 二、基线月费获取

### 2.1 基线来源（优先级从高到低）

1. **资源级账单**：`DescribeBillResourceSummary` 返回的 `RealTotalCost`（按 ResourceId 聚合），从 Step 0.4 预取的 `billing_lookup.json` 读取
2. **产品级均摊**：若资源级无数据（MongoDB / Redis / ES / CFS / NAT / 轻量应用服务器等按集群汇总、ResourceId 对不上账单的产品），用 `DescribeBillSummaryByProduct` 的产品总费用 ÷ 该产品扫到的资源数，展示为 `¥X (=¥总费用 均摊，共N个)` — **这一步必须走，不得跳过直接标"待评审"**
3. **刊例价估算**：级别1/2均无时，按本文件各产品公式估算，标注 `[基于刊例价估算]` 并**不计入总节省合计**

### 2.2 基线月费的时间口径

- 使用**分析月**的 `RealTotalCost`（即本次巡检对应月份）
- 若分析月数据不完整（当月未出账），回退到**上月 T-1** 账单

### 3.1 降配≠释放：HARD 约束（2026-06-11 新增）

> ⚠️ **实测发现的系统性 bug**：降配建议的「预计月省」被错误地按「释放」口径（100%）计算，导致数据库降配节省额被高估约 2-2.5 倍。

❌ [HARD] **所有「降配」类路径的节省比例必须严格使用上表的 ratio%（30%-50%），严禁使用 100%**。

判定依据：降配 = 保留资源运行但缩小规格，节省 = 当前规格费用 - 降配后规格费用；释放 = 退掉整个资源，节省 = 100%。两者含义完全不同，不得混淆。

**正反例**：

| 场景 | baseline | 正确月省 | ❌ 错误月省 |
|------|----------|---------|-----------|
| MySQL 16C32G→8C32G 降配 | ¥1,458 | ¥583 (=¥1,458×40%) | ¥1,458 (=¥1,458×100%) |
| MySQL 2C4G→1C2G 降配 | ¥97 | ¥39 (=¥97×40%) | ¥97 (=¥97×100%) |
| Redis 降内存规格 | ¥863 | ¥345 (=¥863×40%) | ¥863 (=¥863×100%) |

### 3.2 按量 CVM 关机计费规则（2026-06-11 新增）

> 腾讯云按量付费 CVM 关机后分两种计费模式，**月省计算必须区分**：

| StopChargingMode | 含义 | 关机后仍在收费的项目 | 释放后月省 |
|------------------|------|---------------------|-----------|
| `STOP_CHARGING` | 关机不收费（默认） | 仅 CBS 磁盘 + EIP（如有） | **仅 CBS 磁盘费**（CVM计算已停收） |
| `KEEP_CHARGING` | 关机仍收费 | CVM 计算 + CBS 磁盘 + EIP | **baseline 全量**（含计算+磁盘） |

❌ [HARD] **STOP_CHARGING 模式的 baseline 禁止使用 CVM 整机月费**。billing_lookup 中该 CVM 的 cost 可能包含当月运行期间的计算费用，而非仅磁盘费。正确做法：
1. 优先从 billing_lookup 按 CBS 的 ResourceId（`disk-xxx`）查磁盘费
2. 若磁盘 ID 无单独账单条目 → 用 `DiskSize × CBS单价/GB/月`（刊例价兜底，见 analysis-rules.md §CBS F41）
3. ❌ 禁止直接用 CVM 的 billing_lookup cost 作为 STOP_CHARGING 的 baseline

### 3.3 定时关机只省计算费用（2026-06-11 新增）

> 按量付费 CVM 关机后，**计算费用停收、CBS 磁盘费用照收**。因此定时关机的节省只来自计算部分。

**旧公式（已废弃）**：`saving = baseline × 65%` — 把磁盘也算进了节省，高估。

**新公式**：
```python
# 方法1：精确计算（需要拆分计算/磁盘费用）
compute_cost = baseline - cbs_cost  # baseline 已含计算+磁盘，减去磁盘得纯计算
saving = compute_cost * (off_hours / 24)  # 只按关机时长省计算费

# 方法2：简化估算（无磁盘费用明细时使用）
# 典型 CVM 计算:磁盘 ≈ 85:15，每天关 16 小时
saving = baseline * 0.57  # = 0.85 × (16/24) ≈ 0.567
```

| 规格档位 | compute_ratio 估算 | off_hours=16 时简化比例 | 旧比例(65%) | 高估幅度 |
|---------|-------------------|----------------------|-----------|---------|
| 小规格(2-4C) | ~80% | 0.53 | 0.65 | +23% |
| 中规格(8-16C) | ~85% | 0.57 | 0.65 | +14% |
| 大规格(32C+) | ~90% | 0.60 | 0.65 | +8% |

```

  · 中风险需确认：¥X,XXX（占比 X%）
  · 高风险需评审：¥X,XXX（占比 X%）
  · 无基线的行业经验建议：¥X,XXX（**不计入上方合计**）
```

### 4.3 正反例

**✅ passing 示例**（MySQL 降配）：
- 资源 `cdb-xxx`，baseline ¥1,800（来自 DescribeBillResourceSummary）
- 优化路径「MySQL 降配」，ratio = 40%

## 六、历史经验值来源（透明化）

本文件第三章比例系数的参考来源：
- **CVM 降配 50%**：核数/内存线性计费，1/2 规格 ≈ 1/2 价格
- **CVM 停机按量 STOP_CHARGING**：按量关机不收费模式下，CVM 计算已停收，释放仅节省 CBS 磁盘费（2026-06-11 修正，原 100% baseline 含计算费用导致高估）
- **CVM 定时关机 0.57**：`0.85(compute_ratio) × 16/24(off_hours)` ≈ 0.567，取 0.57 保守值（2026-06-11 修正，原 65% 把磁盘也算进节省导致高估）
- **包年转换比例（包年 40% / 包月 25%）**：基于腾讯云官网标准折扣
- **COS 存储类型价差**：基于腾讯云 COS 官方定价
- **数据库降配（30-40%）**：保守估计，因为数据库有额外的管理成本摊入。❌ 降配≠释放，严禁用100%（2026-06-11 新增 HARD 约束，修复实测发现的系统性 bug）
- **竞价实例 80%**：腾讯云竞价实例平均折扣

系数每季度复核一次，若腾讯云调价需同步更新本文件并在 git commit 中说明。
